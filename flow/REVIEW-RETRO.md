# 外部评审复盘：哪些意见有用，哪些我说错了

> 74 轮评审之后的自我校准。用途有两个：
> ① 让主会话知道哪些建议值得优先看；② 提醒「评审意见本身也会出错」，别全盘照搬。

## 一、真的避免了损失的（高价值）

| 问题 | 为什么危险 | 证据 |
| --- | --- | --- |
| **笔记清理脚本盲删** | 删除动作不看标题，`perform action 2` 删的是「列表里任意有删除动作的行」，还清空废纸篓。可能永久删掉用户自己的笔记 | 读了 AppleScript 源码 + 逻辑推演 |
| **验收假绿** | 验收调的是 `envSkipReason`，日志里只要有「环境跳过」四个字，整轮真实失败都被豁免。实测 `npm run accept` 10/10 通过，但 `background-control` 日志里有 `❌ 后台点击计算器按钮` | 同份日志两个函数结果对比 |
| **应用锁会被偷** | 只按 mtime 判过期、无心跳。持锁超过 3 分钟的任务会被后来者抢锁，两个任务同时控制同一个应用 | 可复现 demo：A 还在跑，B 就进去了 |
| **部署漂移** | launchd 起不来（EADDRINUSE），真正服务的是手工启动的游离进程。改了代码永远不生效 | `lsof` + `launchctl print` 对照 |
| **进程孤儿** | 只杀直接子进程，ocu/Chrome 变孤儿；现场抓到 4 个残留，其中一个活了 26 小时 | `pgrep` 现场取证 |

## 二、提升了质量的（中等价值）

- 控制面 token（daemon + overlay 全接口 401）与 Origin 拦截
- 失败归类收窄（ENOENT / 未送达 / ❌ 覆盖）
- 部署守卫 `service:status` / `service:restart`
- `open -g -j` 隐藏启动（不再把测试窗口丢到用户桌面）
- 小窗窗口失效自动恢复（解绑 0.5s / 重绑 1s）
- 日志轮转 `npm run prune`、`status` 报告排序修正
- 文档：绝对化承诺收窄、命令速查、curl 示例带票

## 三、我说错的 / 说早了的（要校准的）

| 我说的 | 实际 | 教训 |
| --- | --- | --- |
| 「CI 三平台必红」 | 49 个测试只有 1 个真 spawn 进程（跑 node），其余是纯函数/字符串断言，测试套件是 hermetic 的，很可能三平台都绿 | 没验证就下的判断要标成假设 |
| 「`patch-publish.diff` 一 apply 就行」 | 仓库变动后补丁过期，不能应用 | 交付物也要定期复验 |
| 「重绑很可能绑错窗口」 | 标题能区分时选得对，只有完全并列才盲选 | 先定量再定性 |
| 「`-j` 会让 AX 读不到」 | 计算器隐藏后 25 个按钮照常可读，只有文本编辑这类需要窗口节点的受影响 | 单点反例不等于普遍结论 |

## 四、四条方法论（这几条比具体 bug 更有用）

1. **每条意见都带可执行验证**。不写「可能有风险」，写「跑这个命令，看这个输出」。
2. **改完要确认调用路径真的走到了**。第 41 轮我修了 `classifyRun`，但验收用的是 `envSkipReason` —— 修了不等于生效。
3. **评审自身会腐化**。文档里写死的数字、代码片段、补丁都会过期；能自动校验的就自动校验。
4. **区分「尝试过」与「最终状态」**。还原前台、发送消息、写文件，用户关心的是结果不是过程。这条在项目里反复出现（假投递、假还原）。

## 五、给主会话的优先级建议

如果时间有限，只看这三件：

1. **业务内容从公开面移除**（唯一可能带来外部麻烦的事）
2. **发布五项**（补丁 + git 身份，半天工作量）
3. **笔记删除的 `[AGENT-TEST]` 标记层**（唯一可能丢用户数据的事）

其余都是「更好用/更好维护」，不阻塞发布。
