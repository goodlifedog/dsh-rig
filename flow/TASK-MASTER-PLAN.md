# 总任务：把项目做成干净可公开的 DSH Rig（用户 2026-11-08 晚确认）

> 作者信息一律用 GitHub 账号的公开信息（网名/头像/noreply 邮箱），仓库与产物里不出现真实姓名、本机用户名、机器名、绝对路径。
> 本文是过程文件，发布前删除。

## 一、隐私与作者（P0，先做）
1. 删除仓库里的个人材料（含身份信息的文档），并清理 git 历史（重写历史或新仓首提交），不留可回溯的个人内容
2. 作者=GitHub 账号；提交身份、包作者、README 作者全部用账号公开信息，不用真实姓名与本机信息
3. 仓库体检加规则：命中个人材料/真实姓名即红；给合法 npm scope、appId 加白名单（否则改名后自己的包名会被判泄露）

## 二、摘掉 目标站点（P0）
4. 删 7 个 写类任务（约 1745 行）、硬编码的站点专用正则、验收里的 scan 项、4 份 目标站点 文档
5. README / CAPABILITIES / ARCHITECTURE / USAGE 里的产品叙事改成通用后台操作叙事

## 三、通用能力与示例（P1）
6. 新增 examples/web-click：任意页面 → 按文字找按钮 → 后台点击 → 读回结果 → 断言，全程不抢前台
7. 验收里用这个示例替代 scan，证明通用网页点击可用

## 四、自主适配 macOS 软件（用户新方向，重点是「自己去做」）
8. **自己决定适配哪些应用**：不要回头问用户要清单。自己按「装机量大 / 有真实操作价值 / 能读出界面树」的标准选，
   选完直接开干；选择结果写进报告（应用、通道、能做什么、风险）
9. **真的实现并跑通**，不是交一份计划：每个被选中的应用都要有可复现的命令、实测输出、矩阵验收记录；
   一次不通就迭代到能用，不许停在「已分析」。
10. **「效果还可以」的判定**（不达成就继续迭代）：
    - 至少 5 个应用能做到「读界面 + 按文字点击/键入」并读回结果
    - 全程不抢前台（矩阵与稳定性任务连续多轮前台不变）
    - 每个应用有一次性跑通的命令与报告，失败能说清是环境问题还是能力问题
11. 读不到或权限缺失 → 环境跳过，不许假绿；任何「看起来成功但没验证到」的结论都不算完成

## 五、测试边界（不可留致命漏洞）
12. 新适配必须复用现有守卫：不覆盖用户数据、不点权限弹窗、不改系统设置、不发危险命令
13. 新代码过静态安全自查 + 权限门禁 + 事件预检三件套
14. 测试只动自己创建的数据，跑完清理；不删用户任何东西

## 六、结构与命名
15. 清理仓库结构：一次性过程记录移出仓库；脚本归位 scripts/；docs 只留规范；删失效补丁
16. 改名 DSH Rig / dsh-rig；launchd 标签换成新前缀；数据目录保留原路径；版本 0.8.0

## 七、内置 ocu（克隆即用）

18. MIT 许可随产物：ocu 的 LICENSE / NOTICE / THIRD_PARTY_NOTICES 进发布白名单；README 注明基于其构建

## 八、可搜索性
19. 仓库 About 中英双语 + 15 个 topics + npm keywords
20. README 首屏：品牌 + 定位 + demo GIF + 徽章 + keywords

## 九、协作方式（以后固定）
21. Lead 派单、监督、抽样核验、统一提交；子 agent 不 commit、不改文档、不跑全量测试

23. 用户 → Lead → 子 agent 单向指挥；Lead 对全局负责
24. 以上为长期模式：以后每个任务都按这套跑，不需要用户每次重新交代派单与监督流程
