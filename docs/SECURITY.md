# 安全边界与测试边界

> 这个工具会在后台操作应用、带录屏权限抓画面、能在本机跑任务。
> 所以"看起来能跑"不够，必须写清楚：哪些攻击面已经堵了、哪些是刻意不做的、哪些还没堵。

## 一、已经在代码里堵住的

| 攻击面 | 后果 | 现在的处理 |
| --- | --- | --- |
| 浏览器页面调本地接口 | 任何网页能读窗口标题（隐私）、往浮窗塞图（钓鱼）、让守护进程跑任务（打字/退出应用） | overlay 7788 和 daemon 7789 都**拒绝带 Origin 的请求**（403），并拒掉跨域预检；POST 必须 `Content-Type: application/json`（415），表单式跨站提交进不来 |
| DNS rebinding 打本地接口 | 网页把 evil.com 解析到 127.0.0.1，同源请求不带 Origin，绕过 Origin 检查直接打到服务 | 两个服务都校验 `Host` 必须是本机回环（127.0.0.1 / localhost / [::1]，含端口），否则 403；**带对 token 也照样拒**（实测两个服务 Host: evil.example 均 403） |
| 本机任意进程驱动守护进程 / 小窗 | 任何本地进程都能 POST /run 让后台跑任务，或调 overlay 读窗口标题、往浮窗塞图 | **daemon 与 overlay 的全部接口都要 `X-Agent-Token`**（唯一例外是 daemon 的 `GET /` 存活探测：只回 ok/pid/uptime，不带任务列表）；token 启动时随机生成写到 `~/.desktop-agent/api-token`（文件 600、目录 700），客户端自动读取；实测两个服务无 token 均 401。默认只认请求头：`?token=` 会漏进 shell history/访问日志，必须显式 `AGENT_ALLOW_QUERY_TOKEN=1` 才认（实测默认下查询串 401） |
| AppleScript 注入 | 应用名/进程名里塞引号或换行把脚本截断，执行任意命令 | 拼进脚本的名字走白名单校验（`isSafeIdentifier`），含引号/反斜杠/控制字符一律不执行；`isSafeScriptLiteral` 再做一层 |
| AppleScript 授权弹窗 | 后台流程被系统弹框打断，或替用户点"允许" | 先用 `AEDeterminePermissionToAutomateTarget(askUserIfNeeded=false)` 静默查授权，没授权**不发 Apple 事件** |
| CDP 端口劫持 | 本地进程抢先监听调试端口冒充 CDP，我们连上去等于把页面内容/输入交给它 | 连之前用 `lsof` 查端口主人：知道应用 pid 时必须相等（`debugPortTrust`）；拿不到 pid 时校验端口主人的可执行路径属于该应用；两者都拿不到就**拒绝连接**（fail closed）。启动和 attach 两处都校验，实机用假 CDP 占端口验证过拒绝路径 |
| pid 复用误杀 | pgrep 和 kill 之间 pid 被系统复用，把用户别的程序 TERM 掉 | 杀之前 `ps -p pid -o comm=` 复核，名字对不上就不杀（`pidMatchesProcess`） |
| 预置可执行文件 | `~/.desktop-agent/bin/ae-permission` 被别人换成恶意程序 | 执行前校验归属和权限（必须本用户所有、不能被组/其他人写），缓存目录不可信时**拒绝执行**；编译走临时文件 + rename |
| 误点权限弹窗（代点授权） | 非中英文系统上，辅助功能/录屏的授权按钮也叫 OK/許可/Erlauben，若按"普通弹窗"点掉就变成替用户授权 | `dialog-guard` 改成结构判定：文案含权限/系统设置线索、按钮像授权（CJK 与拉丁各一套词表）、或弹窗属于系统进程，任一命中就**绝不点**；文案不认识的弹窗默认也不点，只有明确是「崩溃/更新」提示时才点关闭类按钮 |
| 未保存数据被强杀 | 退出应用时如果卡在"要保存吗"，强杀会丢内容 | 退不掉时先查保存/删除类弹窗，有就返回 `needs-confirm` 且不发 TERM |
| 任务名目录穿越 | `/run` 传 `../core/runner` 执行目录外脚本 | daemon 只接受白名单任务名，未知任务 400 |
| 队列无限堆积 | 有人反复塞任务把内存/队列打爆 | 队列上限 50，满了 429 |

以上每一条都有单测或集成测试钉住（见 `test/security-boundaries.test.mjs`、`test/local-token.test.mjs`、`test/overlay-server.test.mjs`、`test/daemon-integration.test.mjs`）。
票据校验用定长比较，长度不同直接拒；token 文件被写坏（不是 32 字节 hex）会重新生成，不会把坏值当 token。
每次启动都会幂等修正数据目录权限（`~/.desktop-agent` 与浏览器 profile 目录 700、token 文件 600）——
`mkdirSync` 的 mode 对已存在的 755 目录不生效，早期版本建出来的目录会被这一步纠正。

## 二、刻意不做的（授权和越权）

- **不替用户点系统授权框**：自动化权限、录屏权限、辅助功能权限都要用户自己点。
  `core/dialog-guard.mjs` 会自动点掉自家软件的崩溃/更新弹窗，但权限类弹窗只提醒、绝不代点；
  判定不靠界面语言（德/法/日系统的权限按钮也叫 OK），而是"权限线索/授权类按钮/系统进程"结构命中，
  认不出来的弹窗默认不动。
- **不控制正在使用的应用**：探测完只关"本轮自己拉起来的"应用；用户已经在跑的应用不重启、不强退。
- **不做不可逆操作**：发送、删除、支付这类动作需要任务显式声明，脚本里默认不碰。
- **不用全局指针兜底**：不通过移动系统指针来点击。

## 三、还没堵的（如实列出）

1. **同一用户下的恶意进程能读到 token 文件**：daemon 与 overlay 的全部接口都要
   `X-Agent-Token`（token 文件 600、目录 700，没 token 一律 401），这挡的是"别的用户 / 浏览器页面 / 误连"；
   但挡不住已经以你这个用户身份运行的恶意程序（它能读你的文件、装键盘记录、读 token）。
   这属于操作系统层面的信任边界，不在工具能解决的范围。
2. **overlay 的 `/windows` 会返回窗口标题**（匹配窗口需要），只对本机进程开放；
   拿到标题就能猜到你开了什么应用。
3. **CDP 通道会真的把应用带着调试端口拉起来**：调试端口对本机所有进程开放，
   是否允许取决于你要不要用这条通道；不用时不要传这个参数。
4. **锁屏下没有任何通道可用**：这不是漏洞，是系统限制，工具会标"环境跳过"而不是假装成功。

## 四、测试边界（我们怎么证明它没坏）

- **会真实操作应用的验收**：矩阵、冷启动、后台控制、终端、浏览器、其他 agent 工具（`npm run bg:verify` 汇总）。
- **只读/离线就能验的**：运行时归类、通道协商、安全纯函数、overlay HTTP 行为（不起应用、不碰前台）。
- **环境不满足时一律"环境跳过"**：锁屏、应用没装、应用没运行，都不会拿"不可读"当"能力缺失"。
- **不许假绿**：分类器把 `❌`、`FAIL` 断言、`结果: 存在失败项` 都当真实失败，
  同一份日志里就算有"环境字样"也不能整轮豁免；环境跳过只认任务显式声明或环境字样，
  不能拿断言名字当豁免理由（评审复现过 form-fill 的 FAIL 被「页面结构已变」吞掉）。
- **不拿用户数据做测试**：测试笔记标题统一带 `[AGENT-TEST]` 标记，清理按标记删（历史测试词要 `--force-all` 才认）；
  标记读不到时退回「写入前后条数差、只删顶部 N 条」，并且要显式 `--force-all` 才允许。
  清理脚本默认只报告；文本编辑只关正文含测试标记的文稿，空文稿不动。
  （实机坑：按"所有可删行"批量删会误伤用户笔记，已修）
- **不在测试里硬重启用户应用**：已经在跑的直接跳过。

## 五、怎么自查

```bash
npm test                            # 全量单测，含安全边界与票据专项
npm run repo:check                  # 文档/命令/绝对路径泄漏等体检
curl -s -H 'Origin: https://evil' http://127.0.0.1:7788/windows   # 应 403
```
